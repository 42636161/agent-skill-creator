## 评价维度与改进方向

### 维度 A：用户交互与对话体验

以 crm-reports-skill 为样本，模拟真实用户在 agent 中调用技能的交互场景，发现以下问题。

#### A-1. 输出呈现缺乏指引

**问题.** 技能产出的是 JSON 报告。用户永远不会看到 JSON——是 agent 读完再翻译给人看的。但 SKILL.md 没有给 agent 任何呈现指引：哪些指标该先说、怎么排序、什么时候该提清洗过程的副作用。结果就是 agent 可能一句"report.json 已生成"了事，也可能啰嗦地读完整个 JSON——用户在不同平台上得到完全不同的体验。

**改进需求.** 技能需要定义输出呈现契约：告诉 agent 拿到 JSON 后应该按什么优先级提取信息、用什么样的结构呈现给用户、在什么情况下主动提跟进问题。

#### A-2. 激活触发词覆盖不足

**问题.** 当前触发词（"clean this CRM export"、"weekly sales report"）代表的是技能作者对技能的理解，不是用户的真实说法。用户会说"帮我看看这个表格"、"这周的数帮我整一下"、"I exported this from Salesforce"——这些表达不包含"CRM"或"report"关键词，agent 不会激活技能。

**改进需求.** 触发词生成应从用户视角出发：覆盖模糊表达（用户不知道这是"CRM 报告"）、覆盖半信息态（用户给了文件但没说清楚要什么）、覆盖多语言（中英文常见的非术语说法）。同时需要在 eval 中增加触发词覆盖检查。

#### A-3. 错误路径静默失败

**问题.** 当输入数据的列名不在技能支持的语言列表里（比如中文列名"区域"、"金额"），技能静默返回空报告而非错误。用户只看到一个空的 per_category，不知道发生了什么。agent 也无从下手——没有错误信息可以翻译给用户。

**改进需求.** 技能在无法匹配列名时应产出结构化诊断信息：哪些列没匹配上、最接近的猜测是什么、用户需要做什么来修复。agent 可以据此向用户报告"没找到金额列，你的列'Deal Value'没在我的支持列表里，要加进去吗？"

#### A-4. 配置项对用户不可见

**问题.** 技能有 6 个可调参数（去重开关、日期格式、异常值阈值、缺失值填充等），但它们埋在 `assets/config.json` 中。用户在对话中不会主动问"异常值阈值能调吗"——因为 ta 根本不知道有这个选项。如果默认参数不适合 ta 的数据，ta 的判断是"这个技能不好用"，而不是"参数需要调"。

**改进需求.** 技能需要在对话层面暴露可配置性：让 agent 知道有哪些参数、默认值是多少、什么情况下应该主动向用户提议调整。同时参数的呈现应该落在用户能理解的语言层面，而不是 JSON key 层面。

#### A-5. 缺少预览确认模式

**问题.** 流水线是一次性操作：读取 → 清洗 → 分析 → 输出。用户无法在清洗步骤执行前预览——ta 不知道会被删掉哪些重复行、哪些值会被标记为异常、日期会被改成什么格式。如果清洗结果不对，用户只能拿到最终报告才知道。

**改进需求.** 技能应支持增量操作模式：先预览清洗计划（哪些行受影响、怎么影响），让用户确认后再执行；或至少支持只清洗不分析的子步骤，让用户可以在过程中检查中间结果。

#### A-6. 不支持对比和历史

**问题.** 技能每次运行都是独立事件。用户每周跑一次报告，但每次都是从零开始——没有上周数据的对比，没有趋势，没有变化幅度。用户拿到一个孤立数字（"总销售额 ¥92,400"），但 ta 真正想知道的是"跟上周比涨了还是跌了"。

**改进需求.** 技能应支持与历史报告的对比：接受一个基线报告路径，在输出中追加对比维度（数值变化、变化百分比、按维度的增减排名）。基线引用应显式传入，不依赖技能自身的持久化状态。

#### A-7. 激活过程对用户不透明

**问题.** agent 激活技能时，用户看不到"现在跑的是 crm-reports-skill"这个信号。用户只看到 agent 开始输出结果，但不清楚这些结果是来自 agent 的基础知识、一个工具调用、还是一个已安装的技能。当结果出问题时，用户不知道应该归因于技能还是 agent。

**改进需求.** 技能在激活时应产生一个轻量的透明度标识——agent 在开始处理前先说一句类似"正在运行 crm-reports-skill，清洗并分析你的 CRM 导出数据"的话，让用户建立清晰的因果链。

#### A-8. 输入格式限制与现实脱节

**问题.** 技能只支持 CSV。但实际 CRM 系统导出的数据经常是 XLSX、XLS 甚至 TSV。用户交过来一个 Excel 文件，agent 要么放弃（"不支持 XLSX"），要么需要额外写代码转换——增加了失败概率和 token 消耗。

**改进需求.** 技能应在入口处处理常见格式差异：自动检测文件类型并在内部做转换，让用户不需要关心"是 CSV 还是 Excel"这个问题。转换失败时应有明确的边界提示而非静默崩溃。
