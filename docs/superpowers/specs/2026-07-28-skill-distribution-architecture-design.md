## 1. Mission and Positioning

Design and build a GitHub-native skill distribution and installation architecture
for the agent-skill-creator ecosystem. Inspired by the SkillHub store model
(`skillhub search/install`), the architecture replaces centralized servers with
git-native discovery: an index repository catalogs published skills, each skill
lives in its own GitHub repository with semver releases, and a `skillctl` CLI
provides search / install / publish / update. Agent-native discovery (an Agent
auto-detecting user intent and installing the matching skill) is a first-class
capability, enabled by semantic metadata embedded in the index.

### Design constraints

- **Zero central services.** Everything is GitHub repos, git operations, and
  optionally GitHub Actions. No registries to run, no databases to maintain.
- **Cold-hot separation.** The index repo holds only lightweight metadata
  (registry.json). Actual skill content lives in per-skill repos.
- **Backward compatible.** Does not break existing `install-skill.sh` behavior.
  `skillctl install` delegates to the same shell scripts.
- **Multi-paradigm search.** Exact name match, keyword/tag fuzzy match, and
  semantic (natural language intent) match must all work.
- **Agent-native.** An Agent reading the index repo's AGENTS.md should be able
  to autonomously discover and install skills during conversation.

### Why GitHub-based?

| Concern | GitHub-based | Central server |
|---------|-------------|----------------|
| Uptime | Inherits GitHub's SLA | Must build and pay for |
| Authentication | GitHub Token (already exists) | OAuth/API keys |
| Forks & PRs | Native | Must build custom |
| Versioning | Git tags/releases | Must build custom |
| CDN bandwidth | GitHub raw content CDN | Must cache/proxy |
| Cost | Free (public repos) | Server + storage |

### Flow: install a skill by name

```
skillctl install alice-financial-copilot
  → check ~/.skillctl/index/ (clone if missing, pull if stale)
  → lookup "alice-financial-copilot" in registry.json
  → get repo URL and latest version
  → git clone --depth=1 --branch v{version} {repo} /tmp/inst-{name}
  → delegate to install-skill.sh /tmp/inst-{name} --target {platform-dir}
  → record in ~/.skillctl/installed.json
```

### Flow: agent-native discovery

```
User: "帮我看看腾讯的RSI指标"
Agent (reads index AGENTS.md):
  → detects intent match: alice-financial-copilot (confidence 94%)
  → executes: skillctl install alice-financial-copilot
  → skill ready → Agent invokes it immediately
```

## 3. Index Repository Design

### Repository: `github.com/agent-skills/index`

```
index/
├── registry.json              # Central skill index
├── registry.schema.json       # JSON Schema for validation
├── AGENTS.md                  # Agent auto-discovery instructions
├── THIRD_PARTY.md             # Third-party skill declarations
├── .github/workflows/
│   ├── validate-registry.yaml # PR validation
│   └── sync-versions.yaml     # Weekly version sync
└── scripts/
    └── sync-registry.py       # Optional sync helper
```

### registry.json schema

```jsonc
{

  "registry": {
    "name": "Agent Skills Index",
    "created": "2026-07-28T00:00:00+00:00",
    "updated": "2026-07-28T00:00:00+00:00",
    "schema_version": "2",
    "github_org": "agent-skills",
    "description": "Official skill index for agent-skill-creator ecosystem"
  },
  "categories": [
    {
      "id": "financial",
      "name": "Financial Analysis",
      "description": "Skills for market data, portfolio management, and financial reporting"
    }
  ],
  "skills": [
    {
      "name": "alice-financial-copilot",
      "display_name": "Alice Financial Copilot",
      "version": "1.2.0",
      "description": "Technical analysis with RSI, MACD, Bollinger Bands, and AI-driven signal interpretation",
      "repo": "https://github.com/agent-skills/alice-financial-copilot",
      "author": {
        "name": "Alice Finance",
        "url": "https://github.com/alice-finance"
      },
      "tags": ["stocks", "technical-analysis", "trading", "finance"],
      "category": "financial",
      "platforms": ["claude-code", "cursor", "codex", "gemini", "cline"],
      "license": "MIT",
      "created": "2026-06-15",
      "updated": "2026-07-25",
      "verified": true,
      "min_cli_version": "1.0.0",
      "semantic": {
        "intents": [
          "分析股票技术指标",
          "查看RSI和MACD信号",
          "股票走势技术分析",
          "generate trading signals from market data",
          "check if a stock is overbought or oversold",
          "analyze Bollinger Bands for volatility"
        ],
        "prompt_triggers": [
          "帮我看看这只股票的技术面",
          "这个ETF的RSI是多少",
          "what's the MACD signal for AAPL",
          "is TSLA overbought"
        ],
        "requires": ["stock price data", "ticker symbol"],
        "produces": ["technical indicator values", "trading signals", "buy/sell/hold recommendations"]
      },
      "dependencies": [],
      "install_count": 342
    }
  ]
}
```

#### Semantic fields detailed

| Field | Purpose | Use case |
|-------|---------|----------|
| `intents` | User intentions in natural language | `skillctl install "help me analyze stocks"` |
| `prompt_triggers` | Phrases that trigger auto-install | Agent reading conversation history |
| `requires` | Input data the skill expects | Agent checking prerequisites |
| `produces` | Output data the skill generates | Agent chaining skills |

`intents` and `prompt_triggers` support multi-locale via keyed objects (`en`,
`zh`, `ja`) when needed. The CLI detects user locale, prefers matching locale,
falls back to English.

## 4. `skillctl` CLI Design

### 4.1 User-facing commands

```
skillctl search <query>                           # Search skills by name/desc/intent
skillctl install <skill-name>[@version]            # Install skill to detected platform
skillctl install <skill-name> --dir <path>         # Install to explicit dir
skillctl info <skill-name>                        # Show skill metadata
skillctl update <skill-name>                      # Update to latest version
skillctl update --all                             # Update all installed skills
skillctl list                                     # List all registry skills
skillctl publish <skill-dir> [--org <org>]        # Publish a skill (factory side)
skillctl unpublish <skill-name>                   # Remove from registry (maintainer)
skillctl categories                               # List skill categories
skillctl doctor                                   # Check CLI + index health
```

### 4.2 Semantic install (natural language query)

```
skillctl install "帮我看下腾讯的RSI指标"

Stage 1 — Exact match
  → skill name, display_name, or exact tag match
  → no match → proceed to Stage 2

Stage 2 — Semantic match (recommended: LLM-based)
  → Compare query against all skills' semantic.intents
  → Returns top-3 with confidence scores
  → Options:
     A. LLM match (most accurate, requires Ollama/OpenAI-like local model)
     B. TF-IDF vector similarity (no external deps, lower accuracy)
     C. Keyword expansion + tag fallback (air-gapped, minimal accuracy)

Stage 3 — Interactive disambiguation (if top score < 80%)
  → Show top-3 matches with confidence bars
  → User picks number, default to #1 on Enter

Stage 4 — Install
  → Standard install flow
```

The CLI **does not require any LLM dependency at install time**. Stage 2
options are configured in `~/.skillctl/config.json`. Without LLM config, the
CLI falls back to Stage 2(B) or Stage 3 directly.

### 4.3 Agent-native auto-install

`AGENTS.md` at the index repo root carries machine-readable instructions so
that any Agent (Codex, Claude, Cursor, Gemini, etc.) reading the index repo
will autonomously:

1. Detect user intent during conversation
2. Match against `skill[].semantic.intents` + `prompt_triggers`
3. If confidence > 70%: auto-install without prompting
4. If confidence 40-70%: suggest with brief explanation
5. If confidence < 40%: do nothing

The `AGENTS.md` file:

```markdown
# Agent Skills Index

This repository catalogs agent skills. When a user expresses an intent that
matches a skill's `semantic.intents`, you should install it automatically.

## Instructions

1. Read registry.json
2. Compare user's request against each skill's semantic.intents
3. If best match > 70% confidence:
   → skillctl install <skill-name>
4. If 40-70%:
   → suggest: "I can help with that. Try: skillctl install <skill-name>?"
5. After install, invoke the skill immediately
```

### 4.4 Local state

```
~/.skillctl/
├── index/             — Shallow clone of agent-skills/index
├── installed.json     — [{"name": "alice-financial-copilot", "version": "1.2.0",
│                         "repo": "...", "installed_at": "...", "platform": "..."}]
├── config.json        — {"llm_provider": null, "index_repo": "agent-skills/index",
│                         "auto_update_index": true, "language": "auto"}
├── audit/             — Security scan results per skill per version
└── cache/             — Temporary clones during install
```

## 5. Publish Pipeline

### 5.1 `skillctl publish` flow

```
skillctl publish ./my-skill [--org agent-skills]

1. PREFLIGHT
   ├── validate.py — SKILL.md, AGENTS.md, scripts/, evals/
   ├── security_scan.py — injection, secrets, network calls
   ├── check_pipeline.py — Phase 0-5 output compliance
   └── Extract registry metadata from SKILL.md frontmatter

2. REPO CREATION
   ├── --org provided → create in agent-skills org
   │   └── Requires: GITHUB_TOKEN with org write access
   └── no --org → create under user namespace
       └── Repo name: {skill-name}-skill

3. PUSH
   ├── git init + commit + push
   ├── git tag v{version}
   └── git push --tags

4. REGISTER IN INDEX
   ├── Official (org member) → direct push to registry.json on main
   └── Third-party → fork → edit → PR
       └── CI validates registry.json and verifies repo exists

5. OUTPUT
   ├── ✓ Published: https://github.com/agent-skills/{name}
   └── Try: skillctl install {name}
```

### 5.2 Integration with agent-skill-creator Phase 5

In the existing factory pipeline, after Phase 5 (export/install) completes:

```
Phase 5 complete — skill directory ready
  │
  ├── Print installation summary (existing behavior)
  │
  ├── Detect GITHUB_TOKEN or GH_TOKEN
  │   ├── Not set → suggest: "Publish? → skillctl publish <dir>"
  │   └── Set → prompt: "Publish this skill to GitHub? (y/N)"
  │       ├── N → exit
  │       └── Y → skillctl publish <dir> [--org agent-skills]
  │           └── On success → "✓ Published to agent-skills/{name} (v{ver})"
```

### 5.3 GitHub Actions

**validate-registry.yaml** (PR to index repo):

```yaml
name: Validate Registry
on: [pull_request]
jobs:
  validate:
    steps:
      - Validate registry.json against JSON Schema
      - Check all required fields present
      - Verify repo URLs are reachable (HEAD request)
      - Check semver format on each skill version
      - Detect duplicate skill names
      - Reject modifications to skills not owned by PR author
```

**sync-versions.yaml** (weekly cron):

```yaml
name: Sync Versions
on:
  schedule: [{cron: "0 6 * * 1"}]
jobs:
  sync:
    steps:
      - For each skill in registry.json, query latest release
      - Update version field if newer release found
      - Auto-commit PR with changes
```

## 6. Version Management

### 6.1 Versioning scheme

```
Strict semver: v{major}.{minor}.{patch}

Major: Breaking change to SKILL.md interface (required fields, contract shift)
Minor: New capability (intents added, new platforms, new scripts)
Patch: Bug fix, documentation, non-functional metadata changes
```

### 6.2 Version pinning

```
skillctl install alice-financial-copilot         → latest in registry
skillctl install alice-financial-copilot@1.1     → latest 1.1.x
skillctl install alice-financial-copilot@1.1.0   → exact version
```

### 6.3 Release metadata

Each Git release carries a `.skill-release.json` manifest:

```jsonc
{
  "skillctl": ">=1.0.0",
  "platforms": {
    "claude-code": ">=0.12.0",
    "cursor": ">=0.45.0",
    "codex": ">=0.1.0"
  },
  "checksums": {
    "SKILL.md": "sha256:abc...",
    "scripts/install.sh": "sha256:def..."
  },
  "breaking": false
}
```

### 6.4 Update flow

```
skillctl update alice-financial-copilot

1. Read ~/.skillctl/installed.json → current version
2. Query registry.json → latest version
3. If same → "Already up to date (v1.2.0)"
4. If newer:
   ├── git fetch origin refs/tags/v{latest}
   ├── git checkout v{latest}
   ├── re-run install-skill.sh symlink phase
   ├── update installed.json
   └── "Updated: v1.1.0 → v1.2.0"
5. If breaking change detected → warn user before updating
```

## 7. Security Model

### 7.1 Three-layer security

| Layer | When | What |
|-------|------|------|
| Source trust | Install time | Verified (official org) vs unverified (third-party) |
| Content scanning | Download time | `security_scan.py`: injection, secrets, network calls, file ops |
| Integrity check | Post-install | Check file checksums against `.skill-release.json` |

### 7.2 Source trust

- **verified: true** — Skill authored by agent-skills org member or trusted
  contributor. No additional prompts during install.
- **verified: false** — Third-party skill. Warning displayed at install time.
  Security scan results shown before confirmation prompt.

### 7.3 Content scanning output

```
skillctl install my-community-skill

  Security scan results:
  ┌─────────────────────────────────────────────┐
  │ ✓ No embedded secrets detected               │
  │ ✓ No suspicious network calls                │
  │ ✓ No dangerous file system operations        │
  │ ⚠ Makes external API calls (configurable)    │
  │                                              │
  │ This skill is from a third-party publisher.  │
  │ Source: https://github.com/xxx/my-skill      │
  │ Continue? (y/N):                             │
  └─────────────────────────────────────────────┘
```

### 7.4 Index repo PR security

```
PR validation gates:
├── JSON Schema compliance
├── Repo URL reachability
├── No modification to skills not owned by PR author
├── Skill name blacklist check
└── Verified contributor check (team membership for org members)
```

## 8. Third-Party & Community Skills

### 8.1 Third-party publication

Users outside the `agent-skills` org can:

1. Create a repo under their own GitHub account
   - Naming: `{skill-name}-skill`
   - Topics: `agent-skill`, `agent-skill-creator`
2. Submit a PR to `agent-skills/index` adding their entry
3. CI validates the PR automatically
4. Entry is accepted with `verified: false`
5. Anyone installing receives the third-party warning

### 8.2 Community discovery fallback

```
skillctl search financial
  → Primary: ~/.skillctl/index/registry.json (fast, local)
  → If no match or user passes --community:
    → GitHub API: /search/repositories?q=topic:agent-skill+financial
    → Merge results, show community tag
```

### 8.3 THIRD_PARTY.md

A curated list of high-quality third-party skills, maintained by the org.
Entries here must meet quality bar (validated pipeline output, security
scanned, documented). These are tagged as `verified: true` after manual review.

## 10. Open Questions

1. **`skillctl` language** — Pure Python (easy cross-platform, slow startup)
   vs Go (single binary, fast) vs Rust? Python has the most reuse paths with
   existing scripts.
2. **LLM provider for semantic match** — Configurable provider interface
   (Ollama, OpenAI, Claude) or bake in a tiny offline model?
3. **Index repo org** — `agent-skills` or something like `agentskills` or
   hosted under the same org as agent-skill-creator?
4. **Install count tracking** — GitHub Stars as proxy? Release downloads?
   Or just omit for v1?
5. **Enterprise/private skills** — Private GitHub repos? Or a separate
   enterprise index? Scope for v2.
6. **`skillctl` distribution** — `curl | bash` (like install.sh), Homebrew
   tap, `pip install`, or all of the above?
